# Birth Register Migration and Integration Analysis

*A self-initiated data analysis case study by Basant Tamang.*

Ward offices hold years of birth registrations in spreadsheets typed by different clerks: dates in two calendars and four formats, missing ward numbers, duplicate entries and phone numbers written five ways. This project analyses such a register, designs a clean database for it, migrates the data with rules that can be checked, and proves nothing was lost.

**Result:** 2,000 records analysed; 1,883 migrated, 57 held for duplicate review, 60 rejected with a reason. All reconciliation checks passed with 0 mismatches.

> **In simple words:** I took a messy old Excel register, counted every mistake in it, designed a tidy database, moved the data across with clear rules, and then proved every single row ended up in the right place.

**All data is invented.** It's generated by a script; no real citizen data is used.

## Scripts

| Script | What it does |
|---|---|
| [generate_register.py](scripts/generate_register.py) | Creates the fake messy register and a list of the problems planted in it |
| [rules.py](scripts/rules.py) | The cleaning and validation rules, written once and shared |
| [profile_register.py](scripts/profile_register.py) | Measures every data quality problem |
| [migrate.py](scripts/migrate.py) | Loads, cleans and inserts the data; sets aside rejects and duplicates |
| [reconcile.py](scripts/reconcile.py) | Runs five checks to prove the migration is complete and correct |

## Run it yourself

Needs Python 3.9 or later.

```
pip install -r requirements.txt
python scripts/generate_register.py
python scripts/profile_register.py
python scripts/migrate.py
python scripts/reconcile.py
```

Results are written to the `output/` folder.

## Nepal-specific detail

Dates of birth were recorded in both Bikram Sambat (BS) and Gregorian (AD). The migration detects the calendar, converts BS dates to AD using the `nepali-datetime` library, and keeps the original text so every conversion can be checked.
